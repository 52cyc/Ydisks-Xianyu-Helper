# 技术设计：批量发布文本清洗与风控分类

## 1. 变更边界

最小行为差距位于三个既有边界：`internal/application/items` 的批量预检文本归一、`internal/adapter` 的平台失败分类、`BatchRunner` 的失败后停止策略。前端只调整新建任务默认间隔，不增加平台协议判断。

不触碰滑块 CAPTCHA、浏览器登录、账号凭证、数据库结构、HTTP 路由和 OpenAPI schema。

## 2. 文本清洗

在 `internal/application/items` 增加纯函数，供 `BatchPreviewService.parseRow` 在校验前处理标题和描述：

```text
原始表格或货源 CSV
  -> HTML 实体解码
  -> 描述常见标签转段落/移除
  -> 控制字符归一
  -> 剩余 < > 转全角
  -> 标题单行化 / 描述段落整理
  -> 现有预检、持久化、发布
```

标签识别只处理规范 HTML 片段；不能把普通数学文本无条件吞掉。无法确认是标签的尖括号保留内容并转成全角。清洗后的内容直接进入预览 DTO，用户看到的内容与最终发布一致。

## 3. 发布错误分类

在 MTOP 发布域提供可测试的“平台已明确拒绝”判定，覆盖：

- 带 `FAIL_BIZ_*` ret 的 `PublishError`；
- 类型化 `MTopErrorBusiness`；
- 类型化 `MTopErrorRiskVerification`。

批量发布适配器在收到上述错误时直接返回确定错误，不包装 `UncertainRemotePublishError`。传输、解码、取消等无法证明结果的错误仍走原防重放分支；远端成功后的检查点失败保持不变。

## 4. 风控停止

为 `BatchRunOptions` 增加消费者定义的 `ShouldStopAfterFailure` 策略。未提供时兼容复用现有 Session 失效判断；组合适配器提供“Session 失效或风险验证”实现。当前风险行先可靠标记失败，再停止 worker，并由既有 `finishInterrupted` 将尚未执行的行保存为可重试的 interrupted 状态。

风控错误不调用自动滑块，不改变现有账号恢复协调。

## 5. 默认发布间隔

`CatalogBatchPanel` 和普通批量发布 Hook 的新建状态默认从 5 秒调整为 15 秒；加载既有批次时优先使用服务端保存值。后端与三方言数据库默认值仍为 5 秒，兼容旧客户端和历史数据。

## 6. 测试与回滚

- 纯函数表格覆盖 HTML、实体、尖括号、控制字符、普通比较文本和空值。
- 适配器覆盖业务拒绝、风险验证、网络未知及检查点失败分类。
- Runner 覆盖风险行后停止、未执行行不调用发布端口及重试状态。
- 前端覆盖两个入口默认 15 秒与历史值恢复。
- 回滚时可分别撤销清洗调用、确定拒绝分支、停止策略和 UI 默认值；数据库无迁移。

## 7. 货源商品删除保护

货源应用服务只把“实例已经成功解析、但详情网关明确查无商品”的结果转换为专用 `ErrProductNotFound`。自动化适配器再转换为消费者定义的 `ErrExternalProductNotFound`，因此调度器无需依赖货源应用包，也不会把实例缺失等其他 `ErrNotFound` 误判成商品删除。

商品页价格扫描遇到该专用错误时改用固定目标价 `9999.00` 元，并继续复用现有闲鱼商品读取、账号可用性检查、远端改价、Cookie 写回和本地价格保存流程。其他报价错误仍只告警并跳过；订单级跟价与采购路径不变。
